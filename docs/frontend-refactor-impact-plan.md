# 前端整体重构与功能审查计划

## 目标与范围

目标是让消费者商城和管理后台的主要流程可靠、易用、易维护，并为功能补齐建立可验证的基线。按影响范围推进：先处理跨端交易与权限，再整理消费者端和管理端体验，最后做性能与清理。后端只在前端流程缺少必要契约时配套调整；支付、数据库结构和外部 AI/QQ 服务不在未经验证时改动。

本项目不是单一 Vue 应用：`user/` 面向消费者，`admin/` 面向商家和管理员，二者连接 `service/` Spring Boot API。改造须保留现有商城功能、API 响应和数据，不以替换框架或清空重做为目标。

## 初始审查结果

| 影响 | 发现 | 证据与含义 |
|---|---|---|
| 高 | 盲盒抽奖不是服务端真实交易 | `user/src/views/User/UserOrders.vue` 在浏览器调用 `Math.random()` 生成奖品并只更新本地订单数组；相关代码标有 TODO。后端目前能查购买资格、创建盲盒订单，但未发现抽奖/履约结果 API。刷新页面后，真实订单不会因此改变。必须先定义服务端原子化抽奖、订单更新和幂等契约，再接前端动画。 |
| 高 | 物流查询未实现 | `UserOrders.vue` 的 `viewLogistics` 只显示“物流查询功能开发中”。订单发货信息虽由后端订单流程维护，用户端尚未提供可用追踪视图。 |
| 高 | 访问控制来源不一致 | `user/src/router/index.js` 在路由 meta 中声明 `requiresAuth`，但 `user/src/permission.js` 以独立白名单决定是否登录；例如人工客服路由声明需要登录、白名单却允许匿名进入。应以明确的访客/登录用户路由矩阵统一实现并回归。 |
| 中 | 前端测试覆盖为空 | 仓库当前没有前端测试文件，后端 `src/test` 文件数也为 0。页面能打开或打包通过不能证明下单、退款、权限等业务正确。 |
| 中 | 两个前端的构建基线不一致 | 管理端 `pnpm build:prod` 成功，但输出包含约 1 MB 和 3.1 MB 的 JS chunk，以及约 487 KB 的 CSS。用户端构建被本机 pnpm 的 minimum-release-age 策略拦截：锁文件中的 `electron-to-chromium@1.5.463` 于检查当天发布；直接调用已缓存的 Vite 也因缺少根 `node_modules/vite` 链接而无法加载配置。这些都还不能证明源码编译失败，不应为通过构建直接放宽策略或重写锁文件。 |
| 中 | 后端构建被 Java 工具链阻塞 | `mvn -pl Neuedu-admin -am test` 在当前 JDK 27 编译失败，报旧 Lombok 生成的 getter/setter 不可见；项目 POM 仍配置 Java 8 与 Lombok 1.18.14。需先选定受支持的 JDK/Lombok 组合，避免把工具链错误误当业务代码错误。 |
| 待确认 | 存在商城之外的遗留页面/API | `user/src/views/enterprise/`、`user/src/api/bid/`、`user/src/api/saleReport/`，以及管理端 `athletes`、`competition`、`ticketsAndAudience` 等目录与 README 的网购商城定位不一致。它们有部分组件引用，且管理端菜单可能来自数据库；在核对菜单/使用情况和产品范围前不删除。 |
| 低 | 有重复或疑似废弃的订单 API | `user/src/api/order/order.js` 请求 `/bid/order/front/list`，当前商城订单页实际调用 `user/src/api/system/orderInfo.js`。先做全局引用和后端路由核验，再决定移除或迁移。 |

本机用户端、管理端和后端开发地址当前均返回 HTTP 200；这只验证服务在监听，不代表登录后的功能流程已通过。管理端构建成功；用户端和后端构建分别受依赖策略与 Java 工具链影响，功能审查因此不能宣称全绿。

## 按影响范围分期

### P0：交易状态、权限和高风险业务契约

覆盖消费者端、管理端和后端 API。先建立匿名访客、已登录用户、管理员的路由/API 权限矩阵，再检查商品浏览、购物车、创建订单、余额支付、取消、确认收货、退款、评价和盲盒各状态转换。

- 盲盒结果必须由后端决定并持久化；前端动画只展示服务器结果。需要幂等、防重复抽取、订单状态校验及失败后可恢复的契约。
- 物流页读取后端已保存的承运和运单信息；没有物流服务时明确显示发货信息和“暂无轨迹”，不伪装成已接入查询。
- 登录、注册、QQ 回调、访客商品页、个人中心、客服页分别定义允许访问的角色和未登录跳转行为。
- 用户订单、管理员订单/退款共用状态定义，避免前端自行修改状态或重复提交。

验收：关键状态迁移有服务端测试；前端有覆盖匿名/已登录、成功/失败/重复提交的测试；刷新页面后订单状态仍与服务端一致；权限矩阵中无 meta 与守卫冲突。

### P1：建立可重复的构建与回归基线

- 固定并记录 Node、pnpm、JDK 版本与仓库现行安全策略。处理用户端 minimum-release-age 拦截时，先核对锁文件版本、发布来源和 pnpm 配置；不通过无条件放宽策略绕过。
- 让两个前端都能在干净依赖环境构建；让后端在明确支持的 JDK 上编译和运行测试。升级 Lombok 或更换 JDK 时需验证所有模块。
- 为关键流程补充自动化：消费者端商品浏览/搜索/详情/购物车/下单/订单操作；管理端商品、店铺、订单、退款；共用 API 错误和权限处理。
- 对支付、短信/QQ、AI、WebSocket 等外部依赖使用可控测试替身；真实联调单独标注，不以模拟测试宣称第三方已验证。

验收：CI 或本地统一命令能重复运行，两端 production build 通过，后端测试通过，失败日志能定位到模块；锁文件在验证过程中无意外变化。

### P2：消费者端信息架构与组件重构

先统一首页、搜索/分类、商品详情、店铺、购物车、个人中心等核心页面的布局、间距、字体、颜色、商品卡片、表单、空状态、错误状态和加载状态。抽取经过至少两个真实页面验证的共享组件，再逐页迁移，避免先造一套无人使用的组件库。

- 优先修复订单页的过长单文件和盲盒相关本地模拟逻辑；将订单状态显示、支付/退款弹窗、评价表单拆成边界清晰的组件或组合式逻辑。
- 保持当前用户端已合并的页面内容与 API 兼容，不以重构为由回退到旧首页或改变业务规则。
- 补齐移动端断点、图片加载失败、空数据、无权限、网络失败和重复点击反馈；关键操作提供明确的禁用/处理中状态。

验收：核心消费者流程在手机与桌面宽度均可完成；现有接口字段不变或有配套迁移；页面状态均有可见反馈；交互测试通过。

### P3：管理端工作流与导航重整

按实际商城职责组织“商品/分类、店铺、订单/退款、用户、评价、客服、系统管理”。把框架自带监控、代码生成、字典等功能放在低频系统区；以角色菜单配置为准，不硬编码替换后端动态菜单。

- 统一列表页筛选、分页、空状态、详情/编辑、删除确认、表单校验和权限按钮。
- 核对 `system/info`、`system/product`、`system/store` 等页面与 API 的字段、状态和操作权限。
- 对赛事、运动员、票务、志愿者等非商城目录先验证数据库菜单和真实使用；确认不属于产品范围后，另行制定移除清单。

验收：管理员和商家角色只看到被授权菜单与操作；商品、店铺、订单、退款主路径有覆盖；动态菜单和深链接可正常工作。

### P4：跨端维护性、性能和可访问性

- 抽查两端请求封装、响应拦截器、登录过期处理、上传和错误提示，减少重复 API 与分散的硬编码路径。
- 按真实路由拆分大页面和依赖，针对大 chunk 做体积预算；只在确认首屏和缓存收益后调整 vendor 分包。
- 清理已由引用分析和菜单核验确认无用的页面/API；不得仅因目录名不匹配而删除。
- 检查键盘操作、表单标签、图片替代文本、颜色对比、移动端触控区域和长内容布局。

验收：主路由按需加载，首屏和总包体积有改造前后数据；没有误删动态页面；关键交互满足键盘和移动端使用要求。

## 建议执行顺序

1. 先解决 P1 的工具链基线，否则无法稳定判断每次重构是否引入回归。
2. 先完成 P0 的订单/权限契约，再改用户端订单页和管理端订单页，避免把错误状态包装得更漂亮。
3. 按 P2 消费者端核心购物路径逐页重构，每个可独立验收的批次单独提交。
4. 按 P3 管理端业务模块迁移，保留动态菜单、角色和现有 API 行为。
5. 最后执行 P4 优化与清理，用构建指标、引用/菜单证据和回归结果验收。

每个批次先记录目标页面/API、调用角色、状态和测试范围，再改代码；完成后跑相关检查并用中文提交。用户要求上传时才推送。数据库重置、迁移或导入 `sports.sql` 不属于前端重构步骤。

## 本轮审查的验证边界

- 已确认：三个本地 HTTP 服务返回 200；管理端 production build 成功；用户端构建受 minimum-release-age 检查拦截且当前依赖链接不完整；后端测试编译在当前 JDK 27/Lombok 组合失败；仓库中没有测试源文件。
- 未确认：真实用户和管理员登录后的完整浏览器流程、支付/QQ/AI/物流等第三方联调、数据库菜单中遗留页面的使用情况，以及受支持 JDK 下的后端构建结果。
