# 前端整体重构与功能审查计划

## 目标与范围

目标是让消费者商城和管理后台的主要流程可靠、易用、易维护，并为功能补齐建立可验证的基线。按影响范围推进：先处理跨端交易与权限，再整理消费者端和管理端体验，最后做性能与清理。后端只在前端流程缺少必要契约时配套调整；支付、数据库结构和外部 AI/QQ 服务不在未经验证时改动。

本项目不是单一 Vue 应用：`user/` 面向消费者，`admin/` 面向商家和管理员，二者连接 `service/` Spring Boot API。改造须保留现有商城功能、API 响应和数据，不以替换框架或清空重做为目标。

## 初始审查结果

| 影响 | 发现 | 证据与含义 |
|---|---|---|
| 已处理（单实例） | 盲盒抽奖原先不是服务端真实交易 | 初审时 `UserOrders.vue` 在浏览器用 `Math.random()` 生成奖品并只改本地订单。现由后端在创建订单时抽取并把奖品明细持久化，前端动画展示服务器返回结果；重复购买资格在单个 Java 进程中加锁。多实例部署仍需数据库级并发/幂等保护，见未完成事项。 |
| 高 | 物流轨迹缺少数据契约 | 用户端订单页现能显示发货时间和“暂无物流轨迹”；订单表只有 `ship_time`，没有承运商、运单号和轨迹字段，因此尚不能提供真实物流跟踪。 |
| 已处理 | 访问控制来源不一致 | 初审时登录守卫的硬编码白名单与路由 meta 冲突。现改由 `meta.requiresAuth` 判断，父路由权限会应用到子路由，并为访客/受保护路由和动态路由注册补充 3 项 Node 测试。 |
| 中 | 前端测试覆盖为空 | 仓库当前没有前端测试文件，后端 `src/test` 文件数也为 0。页面能打开或打包通过不能证明下单、退款、权限等业务正确。 |
| 中 | 两个前端的构建基线不一致 | 初检时管理端 `pnpm build:prod` 成功，但输出包含约 1 MB 和 3.1 MB 的 JS chunk，以及约 487 KB 的 CSS。用户端当时被 minimum-release-age 策略拦截，原因是 `electron-to-chromium@1.5.463` 当天发布。执行阶段将其覆盖到已超过等待期的 `1.5.461`，在 `pnpm-workspace.yaml` 只允许 `esbuild` 和 `vue-demi` 的安装脚本；两项前端现均可 production build。用户端压缩产物仍有约 917 KB 的 Element Plus JS chunk（gzip 约 286 KB），后续可做按需组件/依赖优化。 |
| 中 | 后端构建依赖受支持的 Java 工具链 | `mvn -pl Neuedu-admin -am test` 在当前 JDK 27 编译失败，报旧 Lombok 生成的 getter/setter 不可见；改用本机 JDK 17 后同一 reactor 构建通过。项目 POM 配置 Java 8 字节码目标与 Lombok 1.18.14。建议将 JDK 17 记录为当前验证工具链，并补充测试；JDK 27 不应作为当前构建基线。 |
| 待确认 | 存在商城之外的遗留页面/API | `user/src/views/enterprise/`、`user/src/api/bid/`、`user/src/api/saleReport/`，以及管理端 `athletes`、`competition`、`ticketsAndAudience` 等目录与 README 的网购商城定位不一致。它们有部分组件引用，且管理端菜单可能来自数据库；在核对菜单/使用情况和产品范围前不删除。 |
| 已处理 | 无引用且路由不存在的商城订单 API | 全局确认 `user/src/api/order/order.js` 无调用，后端也没有 `/bid/order/front/list` 或 `/bid/order/orderRefund` 路由；已删除该死代码文件，其他招投标 API 保留。 |

本机用户端、管理端和后端开发地址当前均返回 HTTP 200；这只验证服务在监听，不代表登录后的功能流程已通过。管理端构建成功；用户端和后端构建分别受依赖策略与 Java 工具链影响，功能审查因此不能宣称全绿。

## 按影响范围分期

### P0：交易状态、权限和高风险业务契约

覆盖消费者端、管理端和后端 API。先建立匿名访客、已登录用户、管理员的路由/API 权限矩阵，再检查商品浏览、购物车、创建订单、余额支付、取消、确认收货、退款、评价和盲盒各状态转换。

- 盲盒结果由后端决定并持久化，前端动画只展示服务器订单结果；现有单实例用锁避免重复创建。多实例环境还需数据库事务锁/唯一约束和可重放幂等键。
- 物流页读取后端已保存的承运和运单信息；没有物流服务时明确显示发货信息和“暂无轨迹”，不伪装成已接入查询。
- 登录、注册、QQ 回调、访客商品页、个人中心、客服页分别定义允许访问的角色和未登录跳转行为。
- 用户订单、管理员订单/退款共用状态定义，避免前端自行修改状态或重复提交。

验收：关键状态迁移有服务端测试；前端有覆盖匿名/已登录、成功/失败/重复提交的测试；刷新页面后订单状态仍与服务端一致；权限矩阵中无 meta 与守卫冲突。

### P1：建立可重复的构建与回归基线

- 固定并记录 Node、pnpm、JDK 版本与仓库现行安全策略。处理用户端 minimum-release-age 拦截时，先核对锁文件版本、发布来源和 pnpm 配置；不通过无条件放宽策略绕过。
- 让两个前端都能在干净依赖环境构建；让后端在明确支持的 JDK 上编译和运行测试。升级 Lombok 或更换 JDK 时需验证所有模块。
- 为关键流程补充自动化：消费者端商品浏览/搜索/详情/购物车/下单/订单操作；管理端商品、店铺、订单、退款；共用 API 错误和权限处理。
- 对支付、短信/QQ、AI、WebSocket 等外部依赖使用可控测试替身；真实联调单独标注，不以模拟测试宣称第三方已验证。

验收：CI 或本地统一命令能重复运行，两端 production build 通过，后端测试通过，失败日志能定位到模块；锁文件在验证过程中无意外变化。

### P2：消费者端信息架构与组件重构

先统一首页、搜索/分类、商品详情、店铺、购物车、个人中心等核心页面的布局、间距、字体、颜色、商品卡片、表单、空状态、错误状态和加载状态。抽取经过至少两个真实页面验证的共享组件，再逐页迁移，避免先造一套无人使用的组件库。

- 优先修复订单页的过长单文件和盲盒相关本地模拟逻辑；将订单状态显示、支付/退款弹窗、评价表单拆成边界清晰的组件或组合式逻辑。
- 保持当前用户端已合并的页面内容与 API 兼容，不以重构为由回退到旧首页或改变业务规则。
- 补齐移动端断点、图片加载失败、空数据、无权限、网络失败和重复点击反馈；关键操作提供明确的禁用/处理中状态。

验收：核心消费者流程在手机与桌面宽度均可完成；现有接口字段不变或有配套迁移；页面状态均有可见反馈；交互测试通过。

### P3：管理端工作流与导航重整

按实际商城职责组织“商品/分类、店铺、订单/退款、用户、评价、客服、系统管理”。把框架自带监控、代码生成、字典等功能放在低频系统区；以角色菜单配置为准，不硬编码替换后端动态菜单。

- 统一列表页筛选、分页、空状态、详情/编辑、删除确认、表单校验和权限按钮。
- 核对 `system/info`、`system/product`、`system/store` 等页面与 API 的字段、状态和操作权限。
- 对赛事、运动员、票务、志愿者等非商城目录先验证数据库菜单和真实使用；确认不属于产品范围后，另行制定移除清单。

验收：管理员和商家角色只看到被授权菜单与操作；商品、店铺、订单、退款主路径有覆盖；动态菜单和深链接可正常工作。

### P4：跨端维护性、性能和可访问性

- 抽查两端请求封装、响应拦截器、登录过期处理、上传和错误提示，减少重复 API 与分散的硬编码路径。
- 按真实路由拆分大页面和依赖，针对大 chunk 做体积预算；只在确认首屏和缓存收益后调整 vendor 分包。
- 清理已由引用分析和菜单核验确认无用的页面/API；不得仅因目录名不匹配而删除。
- 检查键盘操作、表单标签、图片替代文本、颜色对比、移动端触控区域和长内容布局。

验收：主路由按需加载，首屏和总包体积有改造前后数据；没有误删动态页面；关键交互满足键盘和移动端使用要求。

## 建议执行顺序

1. 先解决 P1 的工具链基线，否则无法稳定判断每次重构是否引入回归。
2. 先完成 P0 的订单/权限契约，再改用户端订单页和管理端订单页，避免把错误状态包装得更漂亮。
3. 按 P2 消费者端核心购物路径逐页重构，每个可独立验收的批次单独提交。
4. 按 P3 管理端业务模块迁移，保留动态菜单、角色和现有 API 行为。
5. 最后执行 P4 优化与清理，用构建指标、引用/菜单证据和回归结果验收。

每个批次先记录目标页面/API、调用角色、状态和测试范围，再改代码；完成后跑相关检查，以中文提交并推送。数据库重置、迁移或导入 `sports.sql` 不属于前端重构步骤。

## 已执行进度与后续建议

### 已完成

- 已固定仓库验证工具链：`.nvmrc` 使用 Node 24.21.0，两个前端 `packageManager` 锁定 pnpm 12.3.4，`.java-version` 指定后端测试基线 JDK 17；用户端最低 Node 版本设为 20。两端冻结锁文件安装均通过；后台和用户端只允许 `esbuild`、`vue-demi` 构建脚本。
- 新增 GitHub Actions 项目验证工作流，在推送、Pull Request 和手动触发时配置固定 Node/pnpm/JDK 版本并运行统一验证脚本。Linux 验证发现并修复用户中心路由及 8 个子页面导入的大小写错误；新增大小写敏感导入检查，补齐 `ripgrep` 工具依赖并升级已弃用的官方 Actions。随后修复 Java 响应类和过滤器中乱码的注释及默认成功/失败文案，消除编码告警并恢复接口默认提示可读。最新 GitHub Actions 全项目验证通过：Node/pnpm/JDK 固定版本、用户端 12 项测试、两端生产构建、后端 62 项测试均成功；当前仅有 GitHub 关于 `ubuntu-latest` 后续迁移的提示。
- 新增根目录 `scripts/verify-project.sh`，校验 Node/pnpm/JDK 版本并防止公开测试接口白名单回归，随后冻结安装两端依赖、运行用户端测试和两端生产构建、运行后端测试；整套脚本已实跑通过，后端 42 项测试通过。近期新增店铺商品筛选回归用例后，用户端测试为 8 项。
- 安全复核发现并移除了样例 `TestController`：此前 `/test/**` 匿名可访问，会返回写死的假用户密码且提供内存增删改接口；同时移除 `/test/**` 公开白名单，并清空管理端登录表单中的默认密码。使用 clean package 清除旧 class 并重启后端验证，`/test/user/list` 返回应用码 401，公开商品详情仍为 200；管理员登录页不再预填密码。
- 注册成功后原先等待 1.5 秒再跳转，期间用户离开页面仍会被旧定时器拉回登录页；现成功提示后立即以路由替换方式跳转，避免延迟导航干扰浏览器历史。
- 路由访问守卫已改为以路由 `meta.requiresAuth` 为准，动态路由逐条注册，并补充 3 个 Node 原生测试。
- 盲盒奖品由服务端选取、写入真实待支付订单；固定价格由服务端控制，普通下单和购物车拒绝盲盒商品。当前进程按用户串行化抽奖创建流程。
- 盲盒用户锁原先按参与用户永久存入 `ConcurrentHashMap`；现改用固定 512 个锁条带，保持同一用户在单进程内串行化而不随参与人数无界保留锁对象。新增 3 项注册表单测；条带仍仅作用于单个进程，多实例仍需数据库级保护。
- 订单支付接口只允许已实现的余额支付，避免支付宝、微信或银行卡请求绕过实际支付渠道却把订单置为已付款。
- 购物车新增/改数量和结算时按商品表重新读取价格及库存，不信任浏览器传入价格或遗留购物车金额。
- 用户订单页能查看发货时间；由于数据模型没有承运商、运单号和轨迹字段，页面明确说明暂无轨迹。
- 管理端订单详情设为只读；发货改用有状态校验的订单接口，商家端额外校验订单商品必须全部属于本店。
- 每个完成批次均使用中文提交；用户已要求后续批次验证完成后自动推送。
- 首页导航遗留的模拟购物车/订单/收藏/评价数字及未实现请求已移除；首页销量只显示接口真实字段，商品评价空数据或接口失败不再拼接模拟内容。
- 游客可访问的商品、店铺、分类与商品评价查询请求不再附带过期登录令牌；分类搜索页通过公开分类树解析名称，不再请求需要权限的后台分类详情接口。使用本地过期会话验证时，分类搜索和店铺商品仍正常展示。
- 商品详情和盲盒页已去掉无运费模板支持的“免运费”承诺及普通商品页无售后规则支持的“7天无理由退货”；首页页脚服务说明改为项目实际支持的订单查询、店铺发布、售后状态流程和客服咨询，原先无路由的帮助/线下门店等链接改为有效商城入口。
- 修复右侧快捷栏滚动方向判断（之前先覆盖旧滚动位置，导致隐藏条件永远不成立），把未读消息轮询改为 30 秒并在卸载时清理；首页滚动监听也在卸载时移除。
- 智能客服页面卸载时清除 WebSocket 重连定时器、阻止关闭事件再次重连，并移除实际注册的全局键盘处理器，避免离开页面后继续建立连接或遗留事件监听。
- 智能客服不再探测浏览器本机的 `localhost:9091` 并据此误报“后端未启动”；连接状态只由当前配置的 WebSocket 地址反馈，部署环境不再出现与实际连接无关的错误提示。
- 开发环境上传目录改为 `RUOYI_UPLOAD_PATH` 可覆盖、默认使用 service 工作目录下的 `uploadPath`，不再固定到 Windows 盘符；从仓库内已有的图片素材为 SQL 引用的 799 个商品图和 16 个店铺图建立了本机符号链接，图片接口返回 200、商品详情图已在浏览器显示，未改数据库或重复复制素材。3 个 SQL 商品图片文件名在仓库素材目录中不存在，需另找备份才能补齐。
- 首页商品流新增独立网络错误态与重试入口，避免已加载商品后请求失败仍显示“已经到底了”。
- 搜索页分页此前只改变页码，结果列表始终渲染全量数据；现按筛选结果分页，搜索请求采用版本号丢弃过期响应，并把商品/店铺失败显示为错误状态。商品和店铺详情用 SPA 路由打开。
- 店铺详情没有真实评分时此前伪显示 5.0，改为 0.0；同一页面切换店铺 ID 时会重新加载店铺信息、商品和收藏状态。
- 本地访客浏览器复测发现公开商品详情路由虽已实现，但 Spring Security 白名单漏配 `/system/product/public/**`，导致详情接口返回 401；现已补齐白名单。访客点“加入购物车”或“立即购买”时也会先看到登录提示并跳转登录页，登录后保留返回商品详情的地址。
- 店铺详情的访客“关注店铺”入口原先直接调用需要登录的接口，触发过期会话弹窗；现先提示登录并保留当前店铺页作为登录后的返回地址。游客商品搜索分页和搜索结果跳转店铺已在浏览器复测正常。
- 商品详情访客收藏也曾直接调用登录接口；现商品收藏、加购和立即购买共用登录前置检查，分别提示收藏或购买要求，并带回商品详情地址。
- 盲盒详情页访客可浏览商品，但购买此前会直接请求登录接口；现盲盒购买先提示登录，登录后可返回盲盒页继续操作。
- 评价服务中的店铺评分刷新此前是空 TODO；现按店铺全部正常根评价的评分计算平均值，新增、状态审核、编辑和删除根评价时同步更新店铺评分，没有有效评价时归零；后台编辑评价改挂商品时同时刷新原店铺和新店铺，并补充回归测试。
